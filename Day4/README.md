# TodoApi Project Structure

## Main files and folders

- **`Program.cs`** — The application's entry point. It registers services, configures the HTTP request pipeline, maps endpoints, and starts the server.
- **`Controllers/`** — Contains controller classes that handle HTTP requests, such as `GET /api/todos` or `POST /api/todos`.
- **`appsettings.json`** — Stores application configuration, commonly logging settings and other non-secret values.
- **`appsettings.Development.json`** — Optional development-specific configuration. When the environment is `Development`, these settings can override values from `appsettings.json`.
- **`Properties/`** — Contains project properties used by development tools.
- **`Properties/launchSettings.json`** — Defines local launch profiles, such as development environment variables and local HTTP/HTTPS URLs. It is mainly for local development.
- **`TodoApi.csproj`** — The project file. It specifies the target .NET framework and project settings, and may list package references.
- **`TodoApi.http`** — An optional HTTP request file for sending test requests to your API from a supported editor.
- **`bin/`** — Contains compiled build output. Usually generated automatically.
- **`obj/`** — Contains intermediate build files generated by .NET. Usually generated automatically.

## `Program.cs`, line by line

### Explanation

1. **`var builder = WebApplication.CreateBuilder(args);`**  
   Creates the application builder. It prepares configuration, logging, dependency injection, and hosting. `args` contains command-line arguments passed to the application.

2. **`builder.Services.AddControllers();`**  
   Registers the services required for controller-based APIs, including controller activation and related MVC features.

3. **`var app = builder.Build();`**  
   Builds the configured application using the services and settings registered so far.

4. **`app.UseHttpsRedirection();`**  
   Adds middleware that redirects HTTP requests to HTTPS when the HTTPS endpoint is configured. The exact behavior depends on the application's hosting and URL configuration.

5. **`app.UseAuthorization();`**  
   Adds authorization middleware. It enforces authorization policies for endpoints that require them. By itself, it does not configure an authentication scheme or require every endpoint to be authorized.

6. **`app.MapControllers();`**  
   Maps controller routes, including routes declared with attributes such as `[Route("api/[controller]")]` and `[HttpGet]`, so requests can reach the matching controller actions.

7. **`app.Run();`**  
   Starts the web application and begins listening for HTTP requests. The application continues running until it is stopped.

Your actual template may include additional lines, for example OpenAPI/Swagger configuration. Those lines provide API-description or documentation support; keep them if you want that functionality.

## How a request reaches a controller

1. `dotnet run` launches the application using the selected launch profile, if applicable.
2. ASP.NET Core receives an HTTP request.
3. Middleware processes the request.
4. Endpoint routing matches the URL and HTTP method to a controller action.
5. The action returns a result, which ASP.NET Core sends back as an HTTP response.
